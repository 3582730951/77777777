## Current State

Architecture: Go server-rendered templates + HTMX + vanilla JS + custom CSS
Templates: 24 HTML files in internal/admin/templates/
CSS: internal/admin/static/app.css (382 lines, Apple Design System)
Charts: internal/admin/static/charts.js (556 lines, inline SVG)
Reference: sub2api uses Vue 3 + TypeScript + Tailwind CSS (230+ components)

Current design is functional but rough:
- Apple-inspired glassmorphism, light/dark mode auto-switch
- HTMX for dynamic chart updates (hx-get + hx-trigger)
- SSE for real-time audit log streaming
- Custom SVG charts (request series, donut, ring gauge, pool grid)

## Problems to Fix

1. Dashboard data not intuitive enough
   - Missing: cache token statistics (cache_read / cache_creation)
   - Missing: token consumption trend (input vs output over time)
   - Missing: per-provider request breakdown pie/donut
   - Missing: request success rate gauge
   - Account pool grid cards need quota bars (5h/7d) + model list

2. Accounts page too sparse
   - Table-only layout, no visual health indicators
   - Need card-based layout with quota progress bars
   - Need per-account model capability chips
   - Need latency sparkline per account

3. User portal too basic
   - portal_dashboard: only 3 metric cards + key table
   - Missing: usage trend chart, token breakdown, cost estimation
   - Missing: proper onboarding wizard for first-time users
   - Missing: connection test button
   - portal_usage: CSS bar chart is primitive, need SVG chart
   - portal_register: exists but basic

4. Groups page missing info
   - No reasoning_effort / forced_model display in table
   - No system_prompt preview/indicator
   - No live request count per group

5. Visual polish needed
   - Sidebar icons are Unicode chars (should be SVG or better Unicode)
   - Table row hover effects could be smoother
   - Empty states could be more engaging
   - Mobile responsiveness needs testing

## Technical Notes

- Keep Go template + HTMX architecture (no Node build chain needed)
- All charts are inline SVG (no Chart.js/D3 dependency)
- HTMX endpoints: /api/admin/charts/* already wired in handlers_crud.go
- New endpoints needed for dashboard:
  - /api/admin/charts/provider-breakdown (requests by provider)
  - /api/admin/charts/token-trend (input/output/cache tokens over time)
  - /api/admin/charts/cache-tokens (cache_read + cache_creation stats)
- Template helpers available: truncate, join, dict, percent, empty
- CSS variables for theming already comprehensive
