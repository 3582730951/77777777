# 合并 any-auto-register 到 llm-pool 完整实施计划

## Context

llm-pool 是 Go+Vue 多 LLM 账号池网关，现有三个 Group（openai/claude/gemini），每个 API key 绑定一个 Group。any-auto-register 是 Python 自动注册系统支持 11 个平台。目标：合并后实现自动注册→自动入池→统一调度的闭环。

---

## 现有架构关键约束（必须兼容）

1. **Provider 接口**（`internal/provider/provider.go`）：
   ```go
   type Provider interface {
       Name() string
       Invoke(ctx context.Context, account *domain.Account, req *ir.Request) (<-chan ir.Event, error)
       Probe(ctx context.Context, account *domain.Account) error
       Discover(ctx context.Context, account *domain.Account) (*domain.QuotaState, error)
   }
   ```

2. **调度器 PickRequest**（`internal/scheduler/scheduler.go:255`）：
   ```go
   type PickRequest struct {
       GroupID    string
       TenantID   string
       Provider   string      // 必须匹配 account.Provider
       Model      string      // 通过 slotSupportsModel 检查
       ConvHash   string
       SystemHash string
       AccountIDs []string    // 空=允许所有，非空=只从这些中选
   }
   ```

3. **请求流程**（`internal/server/server.go:353`）：
   ```
   API key → auth.Resolve() → Resolved{Group} → PickRequest{Group.Provider, Group.AccountIDs}
   → scheduler.Pick() → Slot → provider.Invoke()
   ```
   - API key 绑定唯一 Group
   - Group.Provider 决定用哪个 provider 发请求
   - Group.AccountIDs 决定候选账号范围

4. **凭证存储**（`internal/store/store.go`）：
   ```go
   type AccountSecret struct {
       Cookies      []byte
       SessionToken string
       RefreshToken string
   }
   // AES-GCM 加密，key = POOL_MASTER_KEY
   ```

5. **Account 结构**（`internal/domain/types.go`）：
   ```go
   type Account struct {
       ID, TenantID, Provider string
       CredentialBlob []byte
       StealthProfile, UA, Proxy string
       State AccountState
       PlanTier string
       Quota QuotaState  // 含 DiscoveredModels []ModelCapability
       Health HealthState
   }
   ```

6. **Python 端 Account API**（`GET /api/accounts`）：
   ```json
   {"total": N, "page": 1, "items": [{
     "id": int, "platform": str, "email": str, "password": str,
     "user_id": str, "primary_token": str,
     "lifecycle_status": str, "validity_status": str,
     "credentials": [{"scope":str, "key":str, "value":str, ...}],
     "overview": dict, ...
   }]}
   ```
   **注意：Python 端没有 synced 字段**，需在 Go 端追踪已同步的 ID。

## 核心设计决策

### 决策1：跨组统一调度

**问题**：现有架构 1 API key → 1 Group → 1 Provider。跨组调度需要一个请求能从多个 Group（不同 Provider）中选账号。

**方案：Group Federation（组联盟）**

新增配置概念 `federation`（联盟），将多个 Group 聚合：

```yaml
federations:
  - id: all-claude-models
    description: "所有能提供 Claude 模型的组"
    member_groups: [claude, cursor, kiro, windsurf, trae]
    api_keys: ["sk-pool-unified-claude"]

  - id: all-openai-models  
    description: "所有能提供 OpenAI 模型的组"
    member_groups: [openai, cursor, windsurf]
    api_keys: ["sk-pool-unified-openai"]
```

**实现**：
- `auth.Resolved` 新增 `Federation *domain.Federation` 字段
- 当 API key 属于 federation 时，构建 PickRequest 不再限定单一 Provider
- 修改 `scheduler.candidates()` 的 Provider 过滤：如果 PickRequest.Provider 为空，允许所有 Provider
- 修改 PickRequest 新增 `Providers []string` 替代单一 Provider（向后兼容：空=不限）
- 合并所有 member_groups 的 AccountIDs 作为候选

**影响范围**：
- `internal/auth/auth.go` — Resolver 支持 federation key
- `internal/scheduler/scheduler.go:310-341` — candidates() 支持多 provider
- `internal/server/server.go:353` — 构建 PickRequest 支持 federation
- `internal/domain/types.go` — 新增 Federation struct
- `internal/config/config.go` — 解析 federations 配置

### 决策2：每个注册平台 = 独立 Provider + Group

每个平台需要独立 Provider（因为调用协议不同），对应独立 Group。

### 决策3：Python synced 追踪

在 Go 端 SQLite 新增 `autoreg_synced` 表，记录已同步的 Python account ID，避免重复导入。

## Phase 4: 调度器跨组支持

### 4.1 修改 `internal/scheduler/scheduler.go`

**PickRequest 扩展**（向后兼容）：
```go
type PickRequest struct {
    GroupID     string
    TenantID    string
    Provider    string     // 单一 provider（现有逻辑）
    Providers   []string   // 多 provider（federation 模式），Provider 为空时使用
    Model       string
    ConvHash    string
    SystemHash  string
    AccountIDs  []string
}
```

**修改 `candidates()`（第310行）**：
```go
func (s *Scheduler) candidates(req PickRequest) []*Slot {
    // ...
    providerMatch := func(accProvider string) bool {
        if req.Provider != "" {
            return accProvider == req.Provider
        }
        if len(req.Providers) > 0 {
            for _, p := range req.Providers {
                if p == accProvider { return true }
            }
            return false
        }
        return true // 都为空=不限制
    }
    
    for _, sl := range s.accounts {
        if !allow(sl.Account.ID) { continue }
        if req.TenantID != "" && sl.Account.TenantID != req.TenantID { continue }
        if !providerMatch(sl.Account.Provider) { continue }
        if req.Model != "" && !slotSupportsModel(sl, req.Model) { continue }
        out = append(out, sl)
    }
}
```

### 4.2 修改 `internal/server/server.go`（第353行附近）

```go
// 构建 PickRequest
var pickReq scheduler.PickRequest
if res.Federation != nil {
    // Federation 模式：跨组调度
    var allAccountIDs []string
    var providers []string
    for _, gid := range res.Federation.MemberGroups {
        g := findGroup(gid)
        allAccountIDs = append(allAccountIDs, g.AccountIDs...)
        providers = appendUnique(providers, g.Provider)
    }
    pickReq = scheduler.PickRequest{
        TenantID:   res.Tenant.ID,
        Providers:  providers,
        Model:      effective,
        ConvHash:   convHash,
        SystemHash: normalize.HashSystemPrefix(req),
        AccountIDs: allAccountIDs,
    }
} else {
    // 原有单组模式
    pickReq = scheduler.PickRequest{
        GroupID:    res.Group.ID,
        TenantID:   res.Group.TenantID,
        Provider:   res.Group.Provider,
        Model:      effective,
        ConvHash:   convHash,
        SystemHash: normalize.HashSystemPrefix(req),
        AccountIDs: res.Group.AccountIDs,
    }
}
```

**关键问题**：Federation 模式下选出的 Slot 可能属于不同 Provider，需要动态获取 provider：
```go
slot, err := g.sched.Pick(ctx, pickReq)
// 根据 slot.Account.Provider 获取对应 provider
prov := g.providers.Get(slot.Account.Provider)
events, err := prov.Invoke(ctx, slot.Account, req)
```

现有代码中 provider 的获取逻辑（确认修改位置）：

```go
// 现有：provider 通过 res.Group.Provider 确定
// 修改为：provider 通过 slot.Account.Provider 确定（slot 选出后才知道）
```

### 4.3 修改 `internal/auth/auth.go`

```go
type Resolved struct {
    Tenant         *domain.Tenant
    Group          *domain.Group          // 单组模式
    Federation     *domain.Federation     // 联盟模式（二选一）
    APIKey         string
    APIKeyOverride domain.APIKeyOverride
}

func (r *Resolver) Resolve(...) (Resolved, bool) {
    // 先检查 federation keys
    if fed, ok := r.byFedKey[key]; ok {
        return Resolved{Tenant: fed.Tenant, Federation: fed.Federation, APIKey: key}, true
    }
    // 再检查 group keys（现有逻辑）
    if res, ok := r.byKey[key]; ok {
        return res, true
    }
    return Resolved{}, false
}
```

## Phase 8: 部署

### Dockerfile

```dockerfile
# Stage 1: Go
FROM golang:1.25-alpine AS go-builder
RUN apk add --no-cache gcc musl-dev sqlite-dev
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=1 go build -o /gateway ./cmd/gateway/

# Stage 2: Python + Playwright
FROM python:3.11-slim AS py-builder
WORKDIR /autoreg
COPY services/autoreg/requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
RUN playwright install --with-deps chromium
COPY services/autoreg/ .

# Stage 3: Vue frontend
FROM node:20-alpine AS fe-builder
WORKDIR /frontend
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ .
RUN npm run build

# Stage 4: Final
FROM python:3.11-slim
RUN apt-get update && apt-get install -y --no-install-recommends \
    libsqlite3-0 libnss3 libnspr4 libatk1.0-0 libatk-bridge2.0-0 \
    libcups2 libdrm2 libdbus-1-3 libxkbcommon0 libx11-6 libxcomposite1 \
    libxdamage1 libxext6 libxfixes3 libxrandr2 libgbm1 libpango-1.0-0 \
    libcairo2 libasound2 libatspi2.0-0 \
    && rm -rf /var/lib/apt/lists/*

COPY --from=go-builder /gateway /usr/local/bin/gateway
COPY --from=py-builder /autoreg /opt/autoreg
COPY --from=py-builder /usr/local/lib/python3.11/site-packages /usr/local/lib/python3.11/dist-packages
COPY --from=py-builder /root/.cache/ms-playwright /root/.cache/ms-playwright
COPY --from=fe-builder /frontend/dist /opt/web

EXPOSE 8787 8788
ENV AUTOREG_PORT=9900
ENTRYPOINT ["/usr/local/bin/gateway"]
```

## 风险与缓解

| 风险 | 影响 | 缓解方案 |
|------|------|---------|
| Python 子进程崩溃 | 注册功能不可用 | manager 自动重启 + 告警 |
| 跨组调度选出的账号 Provider 不支持该模型 | 请求失败 | 依赖 DiscoveredModels 精确过滤 |
| Federation 模式下 model alias 冲突 | 模型解析错误 | Federation 不支持 alias，使用原始模型名 |
| Cursor/Kiro 等逆向 API 变更 | Provider 失效 | 独立 Provider 实现，可快速修复不影响其他 |
| 两 DB 一致性（重复导入） | 账号重复 | Go 端 `autoreg_synced` 表 + 幂等设计 |
| Python 端无 synced 字段 | 无法高效查询 | 优先方案：修改 Python 加字段；备选：Go 端追踪全量 ID |
| Provider 模式为 mock 时新 provider 未实现 | 开发期无法测试 | 所有新 Provider 默认 mock 模式返回测试响应 |
