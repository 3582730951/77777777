Where do I provide my real OpenAI / Claude / Gemini credentials?

The pool currently runs in mock mode by default. To make real upstream calls, you need to enroll a paid web session for at least one provider. Below is the recommended workflow for ChatGPT (OpenAI subscription).

Step 1 — Capture your ChatGPT session

  1. Open https://chatgpt.com in Chrome / Edge and log in.
  2. Open DevTools (F12) → Application → Cookies → https://chatgpt.com.
  3. Copy the value of __Secure-next-auth.session-token (starts with eyJ...) — this is your session_token.
  4. Optionally also copy cf_clearance + __cf_bm for the cookies field below.

Step 2 — Enroll into the pool

Two equivalent ways:

Option A — Web UI: click + Add account, choose provider chatgpt, paste session_token + cookies, save.

Option B — REST API:

curl -X POST http://your-host:8788/api/admin/accounts \
  -H "Cookie: $ADMIN_SESSION" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "openai-1",
    "tenant_id": "default",
    "provider": "chatgpt",
    "plan_tier": "plus",
    "session_token": "eyJhbGc...<your token>",
    "cookies": "__cf_bm=...; cf_clearance=..."
  }'

Step 3 — Switch the gateway to real mode

Edit docker-compose.yml (or your env vars) and set PROVIDER_MODE=real, then restart:

cd /opt/llm-pool
docker compose down
PROVIDER_MODE=real docker compose up -d

⚠️ Note: in this MVP the provider/chatgpt.invokeReal path is a stub. The real reverse-engineered call to /backend-api/conversation still needs to be implemented before real-mode actually exchanges traffic with chatgpt.com. The credentials you enroll are stored encrypted in SQLite and ready to use as soon as that path is wired up.

Same flow for Claude / Gemini

Claude — capture sessionKey from claude.ai cookies. Provider claude.

Gemini — capture __Secure-1PSID + __Secure-1PSIDTS from gemini.google.com. Provider gemini.

Bulk import

curl -X POST 'http://your-host:8788/api/admin/accounts/bulk-import?tenant=default' \
  -H "Cookie: $ADMIN_SESSION" \
  -H "Content-Type: application/json" \
  -d '[{"id":"oa1","provider":"chatgpt","session_token":"..."},
       {"id":"oa2","provider":"chatgpt","session_token":"..."}]'

Or pipe a Netscape cookies.txt file:

curl -X POST 'http://your-host:8788/api/admin/accounts/bulk-import?tenant=default&provider=chatgpt' \
  -H "Cookie: $ADMIN_SESSION" \
  --data-binary @cookies.txt

如何录入真实的 OpenAI / Claude / Gemini 订阅凭证

默认情况下账号池运行在 mock 模式 — 所有 provider 都返回测试响应。要让它真打上游，需要至少录入一家 provider 的 paid web session。下面以 ChatGPT (OpenAI 订阅) 为例说明流程。

第 1 步 — 抓取 ChatGPT 会话凭证

  1. 在 Chrome / Edge 中打开 https://chatgpt.com 并登录你的 Plus / Pro 账号。
  2. 按 F12 打开开发者工具 → Application 标签 → 左侧 Cookies → https://chatgpt.com。
  3. 复制 __Secure-next-auth.session-token 的 Value（很长，以 eyJ... 开头），这就是你的 session_token。
  4. 可选：把 cf_clearance + __cf_bm 也复制下来，保存为 name=value 多行格式（用于 cookies 字段，能减少 CF 验证概率）。

推荐用 EditThisCookie / Cookie-Editor 这类浏览器插件一键导出 JSON，比手抄方便。

第 2 步 — 录入到账号池

两种等效方式：

方式 A · Web UI（最简单）：点击 + 添加账号，provider 选 chatgpt，把刚才抓的 session_token 粘进 Session Token 字段，cookies 多行粘到 Cookies 文本框，保存即可。

方式 B · REST API：

curl -X POST http://你的主机:8788/api/admin/accounts \
  -H "Cookie: $ADMIN_SESSION" \
  -H "Content-Type: application/json" \
  -d '{
    "id": "openai-1",
    "tenant_id": "default",
    "provider": "chatgpt",
    "plan_tier": "plus",
    "session_token": "eyJhbGc...<你的 token>",
    "cookies": "__cf_bm=...; cf_clearance=..."
  }'

第 3 步 — 切到 real 模式

修改 docker-compose.yml 或 env，把 PROVIDER_MODE=mock 改成 PROVIDER_MODE=real，然后重启：

cd /opt/llm-pool
docker compose down
PROVIDER_MODE=real docker compose up -d

⚠️ 重要说明：当前 MVP 里 provider/chatgpt.invokeReal 是占位实现 — 凭据会被加密保存到 SQLite，但调用 chatgpt.com 的反向工程逻辑（arkose token、/backend-api/conversation 协议解析）需要后续完成才会真正打上游。你现在录入的 cookies/token 不会丢，等那一步打通后立即生效。

Claude / Gemini 同流程

Claude：在 claude.ai cookies 里抓 sessionKey，provider 选 claude。

Gemini：在 gemini.google.com cookies 里抓 __Secure-1PSID + __Secure-1PSIDTS，provider 选 gemini。

批量导入

JSON 数组：

curl -X POST 'http://你的主机:8788/api/admin/accounts/bulk-import?tenant=default' \
  -H "Cookie: $ADMIN_SESSION" \
  -H "Content-Type: application/json" \
  -d '[{"id":"oa1","provider":"chatgpt","session_token":"..."},
       {"id":"oa2","provider":"chatgpt","session_token":"..."}]'

或者直接传 Netscape 格式的 cookies.txt：

curl -X POST 'http://你的主机:8788/api/admin/accounts/bulk-import?tenant=default&provider=chatgpt' \
  -H "Cookie: $ADMIN_SESSION" \
  --data-binary @cookies.txt

安全提示

  • 所有凭据用 AES-256-GCM 加密存进 SQLite，主密钥在 POOL_MASTER_KEY 环境变量里 — 不要提交到 git
  • 登录 ChatGPT 时关掉 Memory 个性化（Settings → Personalization → Memory: Off），避免账号切换时模型回答风格漂移
  • 把订阅版伪装成 API 调用通常违反 OpenAI/Anthropic/Google 的 ToS，可能导致账号被封 — 自评估风险
  • 建议每个账号绑独立的住宅代理（在 HTTP 代理字段填），避免多账号共用一个公网 IP 触发风控

CLI 工具接入配置

Codex CLI 接入

Codex CLI 使用 ~/.codex/config.toml 配置 base_url，不是环境变量。

# 方法 1: 使用脚本自动配置
bash scripts/setup-codex.sh http://你的IP:{{.GatewayPort}} sk-pool-你的key

# 方法 2: 手动编写 ~/.codex/config.toml
model_provider = "llmpool"
model = "gpt-5.2"
model_reasoning_effort = "high"
disable_response_storage = true

[model_providers.llmpool]
name = "llmpool"
base_url = "http://你的IP:{{.GatewayPort}}"
wire_api = "responses"

同时写入 ~/.codex/auth.json：

{
  "OPENAI_API_KEY": "sk-pool-你的key"
}

Claude Code 接入

# 设置环境变量
export ANTHROPIC_BASE_URL=http://你的IP:{{.GatewayPort}}
export ANTHROPIC_API_KEY=sk-pool-你的key

# 然后正常运行 claude
claude

Gemini CLI 接入

# 设置环境变量
export GEMINI_API_BASE=http://你的IP:{{.GatewayPort}}
export GEMINI_API_KEY=sk-pool-你的key

# 然后正常运行 gemini
gemini
